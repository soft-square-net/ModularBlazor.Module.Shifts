# ModularBlazor.Module.Shifts

Shifts: newsroom sections, the rota (Manager, Desk, Editor) and check-out; the rota becomes time-windowed grants. It is a module of the [ModularBlazor](https://github.com/soft-square-net/ModularBlazor) platform, released on its own as the bundle `shifts`.

> **Status: scaffold.** The code still lives in the platform repo, under [`src/WebApi/Modules/Custom/Shifts`](https://github.com/soft-square-net/ModularBlazor/tree/main/src/WebApi/Modules/Custom/Shifts).
> It moves here, and is removed from the platform in the same step, once the platform publishes its contract
> packages. Until then, develop it in the platform repo.

## Layout

```
src/WebApi.Modules.Shifts.Domain/           entities, aggregates, domain rules
src/WebApi.Modules.Shifts.Application/      use cases, DTOs
src/WebApi.Modules.Shifts.Infrastructure/   entry assembly: IRuntimeModule, endpoints, DbContext, tenant migrations
src/WebApi.Modules.Shifts.Client/           typed API client (NSwag), shipped as a hidden client module
openapi/   the saved OpenAPI document the client is generated from
playground/   Aspire AppHost for local development
tests/
module.json   bundle manifest, generated by the pack step
```

## How it builds and ships

- It compiles against the platform's contract packages (`WebApi.Contracts`, `ModularBlazor.Abstractions`, ...) from the
  soft-square-net GitHub Packages feed. It never references platform source.
- CI packs one bundle per release: `<module>-<version>.modpkg`, a zip with `module.json`, `server/`, `client/` and
  `contracts/`. The platform's admin area installs it: server part first (tenant migrations), then the client part.
- One version for the whole bundle, set once from the git tag. Unchanged parts are skipped on install.
- An API client ships once, inside the bundle that owns the API, as a hidden client module. Modules that call it
  reference its package with `ExcludeAssets="runtime"` and declare a dependency with a version range in `module.json`.

## Developing

`playground/` will hold a small Aspire AppHost: the platform's containers (gateway, WebApi, identity, Blazor client)
plus this repo's projects, loaded from their build output, so F5 shows a change without packing or uploading.

## Branches

Trunk-based: `main` always produces an installable bundle; short-lived `feat/...` and `fix/...` branches; a release
is a tag such as `v1.2.0`.
